# 目录维护规则

[English](maintenance-policy.md)

`catalog/` 下的机器可读文件是唯一事实源；中文叙述翻译保存在 `catalog/i18n/zh-CN.yaml`。`README.md`、`README.zh-CN.md`、`dataset-cards/` 和 `suite-cards/` 都是生成视图。修正事实时，应在 YAML 中附字段级一手来源，并同步翻译且不增加新主张，然后运行生成器。公开仓库保存描述与链接，不保存上游数据集或凭据。

## 审查周期

- 每次贡献都需通过 schema/引用检查、生成文件一致性检查、凭据及私有路径扫描和测试。维护者应对数据集角色、证据粒度、规模、许可及官方指标的变更核对所链接来源。
- 如条件允许，每季度复查访问 URL、归档/弃用公告、官方数据卡、许可和仍有冲突的计数。`last_checked` 是**字段复核日期**，不是成功下载的证明。
- 上游发布新版时，应先比较版本与划分协议再编辑原记录；若语义或评测方式改变，则建立单独变体，不覆盖历史结果。

HTTP 403、429、身份验证要求及 robots 限制，都不能证明数据集已经消失。记录访问问题的日期和方法，不能因为一次请求失败就删除条目。只有核实后，才用作者控制的权威地址或归档引用替换失效链接。

## 纠错与状态提升

提出纠错时提供准确字段、现值、建议值、一手来源 URL、来源摘录或行号、核对日期及受影响版本。官方统计冲突时，保留两种单位或变体，并说明目录描述的是哪个发布版本。关键字段完成核对后，审查者可以把 `screened` 提升为 `source_checked`。`reproduced` 需要有记录的数据加载和评测器运行；`verified` 还需独立的第二次审查。定时任务不能仅凭链接可访问就推断这些状态。

来源链接能支持主张，但外部页面也会变化。尽可能固定论文 DOI/arXiv 编号或发布标签，并记录访问日期。数据集自身许可优先于目录文字的许可；没有明确权利时，不镜像来源文档、隐藏标签或受访问限制的文件。

## 发布与兼容性

Schema 变更要写入发布说明。增加可选字段通常兼容；若改变枚举含义或必填字段，应提供迁移说明并更新校验器。CI 检查生成的 Markdown 是否漂移。发布说明应按审查状态报告条目数量，以及新增、移除和事实纠正，不能暗示已经覆盖整个生态。

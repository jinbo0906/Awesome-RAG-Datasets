# 不依赖特权分块的证据真值

[English](evidence-ground-truth.md)

通常不存在脱离上下文的“正确分块边界”。边界取决于问题、来源结构、检索器和 token 预算。若用另一种分块器生成的 chunk ID 给候选分块器打分，benchmark 就会循环定义真值。应把金标准证据锚定到不随策略变化的上游来源坐标，把分块输出视为**预测结果**，看它是否覆盖这些坐标。

## 锚定来源的证据记录

记录来源资产的哈希或版本、文档 ID、解析器版本、页码和坐标系。文本节点可用 UTF-8 字节偏移或 Unicode 字符偏移，但必须明确选择；视觉节点可用归一化页面 `bbox`、稳定单元格 ID 或图形 ID。原始文件与 OCR/解析视图要分别保留。每个答案关联原子事实，以及一个或多个可接受的证据集合。多跳答案要求某个可接受集合中的每项事实都得到支持；等价的支持路径要分别保留。

[证据 JSON Schema](../schemas/evidence.schema.json)定义了小型交换对象；`awesome_rag_datasets.evidence.validate_evidence` 还检查节点、边与事实的引用，以及坐标顺序。这**不表示**当前目录中的所有数据集都已经拥有这些标注。转换适配器应将不可获得的字段留空，并记录有损映射。

## 分块实验

| 层级 | 指标 | 含义 |
|---|---|---|
| 结构 | 边界 precision/recall、事实被切断的比例 | 仅作诊断；落在标题处的边界本身不等于充分证据 |
| 检索 | 完整证据集合 Recall@K、首次完整覆盖的排名 | 只有至少覆盖一组完整可接受证据时，该查询才算成功 |
| 效率 | 金标准 token 比例、非真值 token 开销、索引大小、延迟 | 避免整篇文档作为一个 chunk、靠无限上下文取胜 |
| 回答 | 事实覆盖、答案 EM/F1、引用支持程度 | 测量下游效用，同时不与检索分数混为一谈 |
| Oracle 差距 | 提供金标准证据与使用实际检索证据时的回答差距 | 区分生成失败和检索失败 |

主要对比实验应固定来源文档、问题、embedding 模型、检索器、重排器、生成器和 token 预算，只改变分块。之后至少换用两种检索器或生成器主干做敏感性分析。报告同一查询上的配对差异及不确定性，不能只报总体均值。除 chunk 数外，还应按找回的**token 数**比较；重复和重叠预测也需明确处理。绝不能用待评估分块器的输出定义真值。

适合起步的候选包括：HiCBench 的结构边界与问答，HotpotQA/2WikiMultiHopQA 的支持句，QASPER 的长论文证据，以及 CLAP NQ 的非连续句子支持。这些数据互补而不等价：支持句对原子事实可能过粗，对连贯 chunk 又可能过细。

## 多模态证据图

证据节点可以是有来源依据的文本片段、页面区域、图形、图注、表格单元格、图表标记、公式或视频时间区间。边记录 `supports`、`required_with`、`caption_of`、`row_header_of`、`column_header_of`、`continued_on`、`refers_to`、`corefers_with`、`temporal_before` 等类型。只有某一组可接受链条所需的**节点和关系**都存在，才算完整。

应分别评测文档/页面检索、节点召回、边正确率、完整链条召回、答案正确性和事实到来源的引用。区域匹配要先定义坐标归一化和 IoU 阈值。比较金标准版面 oracle、解析视图和最终流水线，才能把解析/OCR 错误与检索错误区分开。仅找回图注，或找回数值却遗漏表头和单位，可能有较高节点召回，但完整证据链仍失败。

MMDocIR 提供页面/版面检索标注；MMDocRAG 增加答案与证据分析；XL-DocBench 有页面和片段证据；MAVIS 关注事实级多模态引用。SlideVQA 有证据页面标签，但其通用版面框不全是针对具体问题的标注。这些差异决定了证据图中哪些组成部分可直接评测、哪些需要新标注。

## 负责地构建新标注

先选 200–500 个分层样本，涵盖纯文本、表格—文本、图—图注、跨页和跨文档场景。标注者应直接面对固定的来源资产，记录多组最小充分证据，并纳入不可回答及误导性证据案例，再裁决分歧。发布标注说明、来源哈希、划分逻辑、标注者间一致性、可接受替代证据和少量人工复查样例。模型辅助提出的候选在人工核对前只能称为候选。只有来源坐标、许可、评测器和基线输出可被独立检查，新 benchmark 才具备公开发布条件。
